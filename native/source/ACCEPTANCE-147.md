# CL 0.147 native-end-to-end acceptance: evidence transitions on caller-owned byte stores

A host currently can prove a frozen evidence journal without filesystem access, but cannot initialize or change that journal through the pure C SDK. The capability block completes native evidence lifecycle (init, observe, withdraw, restore, reconcile, seal, verify) without a file adapter. The SDK proposes new evidence bytes; the external data owner chooses whether and how to persist them. PCGM retains identity, choice and commit authority; this is not PCGM policy editing or rollback.

- Same canonical snapshot and receipt as the current durable CLI for the same exact input package, goals and batch frame. Share implementation of transaction preparation between CLI and buffer SDK. Distinguish no host write implied by a returned hypothetical proposal from the file adapter's actual durable publication.
- Require verified old snapshot bytes pinned by SHA-256 and exact expected revision for new batches; replays only if tx ID binds identical frame bytes on a supplied descendant that records the receipt. Two independently computed proposals do not grant two writers; consumer must compare-and-swap current head. Document what signatures and digests do not authenticate.
- Return candidate snapshot and receipt atomically at the ABI boundary; rejected request, stale pin, mismatched package/goals/pins, malformed rows, changed duplicate tx, or failed proof budget have no partial output. No opaque process handle required for restart. Do not mutate any caller buffer or read any path.
- Test independent C host loaded from copied shared library (no CLI executable or write target at execution); initialize, commit a candidate, reopen from bytes in a different executable, named replays, rollback of *CL evidence row activity* and exact proof parity with current file CLI; byte corruption refuses without output. Existing buffers, profiles, proofs and PCGM semantics retain old compatibility. Real native Linux tests, no Windows/CUDA claims.
