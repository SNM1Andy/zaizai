# CL 0.150: independent evidence of exact checkpoint origin

Separate receipt byte integrity from semantic validity. Keep the fast reopen path for checkpoints from the user's already authorized writer. The new audited path requires the original pinned package and goals, pinned checkpoint and expected limits, recomputes precisely the claimed prefix in native CL, and compares the canonical checkpoint bytes (facts/proofs, frontier, counters, projection masks). Reopening on the checked path must continue that independently computed state, not import candidate facts. This takes compute proportional to prefix length and grants no PCGM policy authority.

Acceptance: use a real nontrivial recursive native CL package; pause/kill writer, remove source, verify the checkpoint from relocated C memory SDK and separate CLI, then continue to identical final proof. Independently supplied changed/inconsistent bytes fail even when their outer digest matches. Verification rejects wrong goal, package, ceiling, excessive rounds and a claimed terminal frontier. Pure SDK performs zero filesystem operations. Existing fast reopen and old checkpoint envelopes stay compatible. Linux CPU only.
