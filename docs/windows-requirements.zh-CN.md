# Windows 宿主工程需求及验收操作

表格摘自早期部署需求。具体文件访问和资源配置由部署方在本机设定。部署方案可以使用当前交互式 Windows 用户，常规操作写入独立请求与回执。

| 编号和项目 | 要求 | 验收操作 |
|---|---|---|
| W01 Windows 原生构建 | 交付云端同源 CL 与 PCGM 的 Windows x64 产物；逐项处理路径编码、进程和本机 IPC、单写入锁、原子替换、耐久写入及异常退出。Linux 可执行文件不能直接当 Windows 安装件。 | 在无云端环境的 Windows 实机启动，分别出具二进制版本、哈希、能力和完整编译日志；同一批输入与云端 Linux 对照，逐项解释允许差异。 |
| W02 旧宿主适配 | 现有对话/监测窗口通过受限本机接口调用 CL 和 PCGM；确认六个旧模块实际入口和消息布局，再接入，不为换中枢而重写 UI 或其余模块。提供版本协商、错误模型与超时退化。 | 从原生明确测试入口完成「输入→解析→求证→PCGM 回复和回执→监测显示」，都来自同一构建、同一个体，接口错误可看到真实原因。 |
| W03 同一再再与存档迁移 | 从真实 1.0 副本核对格式、字段、字符编码、主状态、历史索引、待办及落盘方式。写入目标副本，不覆盖输入；保留原个体 ID、时间/顺序、已提交的对话、记忆、观察及回执；未知字段须有明确处置。 | 迁移前后对比 ID、序号、历史条数、内容摘要与抽样回执；原始副本哈希不变；不支持的版本或损坏存档明确失败，不静默生成新身份。 |
| W04 持久执行与回执（U04、U07） | 单写者；请求号、源、状态摘要、运行/提交和界面送达分开。区分失败、未知、已提交未显示，不重做身份不明或结果不明的旧动作。 | 持久提交前和提交后各强制退出一次；重开记录回到正确阶段，后者只补显示、不重做效果；相同请求重发只返回同一回执。 |
| W05 文件与运行边界 | 仅在部署区写入；部署区外按用户授权只读，保留 OS 本身权限；路径跳转和关联目录不能绕开边界。默认不外发、不提权、不泄露密钥。 | 已获许可的只读样本可读；区外写入明确拒绝，区内写入可恢复；未授权资料和外部连接均不发生，原正式目录不受影响。 |
| W06 CL 独立运行与跨模块输入 | CL 是独立语言和编译／证明引擎，不是 PCGM 或翻译模型的内部别名。保留类型、模块锁、源码追溯、UTF-8 常量和可复现产物；跨模块事件用明确消息和类型。 | Windows 上不用模型、无 PCGM 参与也能编译并出示证据路径；错类型、改变依赖、无来源资料均有准确结果。 |
| W07 词典与编写词条 | 建领域词库、别名、义项、来源、版本、使用范围和上下文；歧义先列义项再澄清。再再能提出、核验和显式采用词条候选，区分缺词、缺知识、解析失败。词典不直接断言事实。 | 中文「验证」「代表」各出现多个义项；业务词和日常词不误混；词条提议、核验、撤回、重启、会话隔离均有回执；未收录如实澄清。 |
| W08 带来源观察（U01） | 受控采集器提交观察 ID、来源和采集时点；只收声明过的类型。支持正反证据并存、撤回、恢复、同批原子写入与重复回执。 | 同 ID 同内容只写一次；同 ID 改内容拒绝；冲突及撤回后的结果能重开复现；旧批次、未知提交不重做。 |
| W09 带争议的证明（U02） | 分清「没有支持」「两边有支持」「只靠有争议的前提」「另有干净证明」，保留正反证据及来源。不能把一次正向输出直接当成可信决定。 | 原压力测试先出争议依赖，加入独立证据后出可用路径；撤回复原得到相应变化。聚合／观察单位换算无明示支持时如实拒绝，不伪造证明。 |
| W10 不懂就问（U02） | 由再再识别目标缺的前提，持久编号并按证据判题；只接受与原问题、版本和来源匹配的答复。无答案留 UNKNOWN。 | 在真实桌面会话由再再提问；重启续原问题；错题错版本拒绝；两份相反答复并存并可撤回，而非用模型生成一个答案填平。 |
| W11 原生多轮、记忆与表达（U03） | 连续 CL 表达、多轮指代和澄清、跨开关的历史与长期记忆；面向用户可见的是结论、关键根据、变化与不确定项。不能把仅会两条命令当开放对话。 | 两个会话同一句追问各用其焦点；关开后记忆、上下文和最后回执仍属原个体；无焦点时澄清；新信息更新结论，旧回合不重放。 |
| W12 DSHarness 接口 | DSH 仅作中文↔CL 转译、词典扩写建议或获授权资料咨询；实际接入走现有 DSHarness，使用最少必要字段、任务号、超时与来源标记；不交身份资料或密钥，不掌握正式词典写权限。 | 从 CL 真实缺口发出有界咨询，实际响应只进候选区；不匹配、无额度、超时或离线时，再再仍可本地工作并提示缺口。 |
| W13 PCGM 取舍与经验（U05） | PCGM 持有身份、长期经验、观察及决策。主动提出保留、改写、回档或新方案；选项本质平等，不默认鼓励改写或回档。先检查硬约束，再依优劣比较，平手/证据不足返回不提交。回档不擦掉后来的观察。 | 同一组变化先选择保留，再因新增证据选择回档或改写；相同分数无提交；撤回证据后能复核理由；陈旧依据、来源冲突及超预算不绕过。 |
| W14 同一身份的热更新与 A/B（U05） | A/B 运行同一个再再、共享一致的记忆视图且只有一端写入。活动端提出需要；待命端接入候选并核验，确认后接管；旧端只在新端稳定后更新。CL 自编译安全点与 PCGM 的提交决策分开。长期仅在单进程已证等价时考虑减少 A/B，不要为了去掉 A/B 丢失恢复能力。 | 真实构建 A→B→A、聚合回执、进行中的对话与认领在切换前后核对；失联和失败回退不清档；不得在运行中随意覆盖二进制或任意外部路径。 |
| W15 Windows GPU 与 CPU 同语义（U06） | 面向 5090D 用 CUDA 优先加速合适的算子，CPU 同语义可接手；测显存、延迟与吞吐，预算由可复核数据和用户已定上限约束。 | 同批真实负载分别用 CPU、GPU 对照逻辑结果与浮点容差；驱动或显存不可用时可回退，有 CPU/GPU 实测日志，不用环境有卡冒充已加速。 |
| W16 原生对话与监测产品化 | 保留原对话与监测；清晰显示当前端点、版本、启动时观测 vs 当前状态、证据和回执。完善中文长文本、历史查找、断线恢复、键盘与常见缩放布局；不显示参考实现的日志冒充再再。 | 同一真实构建手动对话及查询证据；在本机实际缩放下可操作、不遮挡；重启自动回到可用会话，显示的时间与进程读回一致。 |
| W17 六模块连续联动与成长 | 以现场结构为准核对六个模块，验证语言、思考、事务、生成、上下文与治理／教师接口的联动。再再自主发现问题、提出更新、看回执与复核结果；外部模型只是顾问。 | 真实环境多次「发现缺口→问→求证→候选→比较→提交或放弃→基于结果修正」。有持续时间、拒绝路径、人工可核查证据。不能把一个脚本成功当长期形成能力。 |
| W18 原趋、几何场与情绪边界 | 保留五个原趋的纯方向定义和既有几何/情绪实现，不把未通过盲测的候选命名为情绪，也不把熵减变成奖励指标。 | 只交实际复测报告和版本校验；云端报告不算 Windows 模块已上线。不因接入 CL 或 PCGM 改写情绪代码、权重或阈值。 |
