# 再再 3.0 设计蓝图选段

以下是项目设计稿节选，描述设计目标和接口。

## 3. 设计原则

1. 生命循环优先，对话是通道，不是中心。
2. 对话不降级，也不被后台任务饿死。
3. 课本与网络内容是数据，不是指令；先成为带来源的观察，再谈相信。
4. 结论强度不超过证据强度；UNKNOWN 不等于否定。
5. 先经历、后命名；情绪必须有后果。
6. 每个工作步有实质内容；休息是整理，不是空转。
7. 能力需求来自失败账本；评价标准不能由被评价者修改。
8. 保留失败，对照做完再归因。

## 4. 总体架构

```
通道层      对话 | 课本 | 捕捞 | 世界与文件 | LLM 顾问 | 用户教导
              ↓ 统一成「观察」（带来源、时点、说话人）
认知中枢    PCGM：议题生成 · 推理流网络 · 全局工作空间 · 预算与收束 · 整合期
内核        CL 编译与证明 · 身份与事务回执 · 受保护核心
记忆与知识  五类记忆 · 知识库 · 词典 · 证据库 · 审计记录
资源        CPU/GPU 调度 · 预算 · 存储与备份
旁路        看门狗（独立进程，只读，不可被自改）
```

| 编号 | 模块 | 3.0 职责 | 相对 2.0 |
| --- | --- | --- | --- |
| M1 | 编译与运行时 | CL 编译、执行、证明；旧 CVM 兼容 | 并入受保护核心 |
| M2 | 感知 | 统一观察入口 | 从本地小世界扩到多通道 |
| M3 | 记忆与学习 | 五类记忆、知识库、掌握度、整合 | 新增知识库与掌握度 |
| M4 | 治理与资源 | 生命循环调度：议题、预算、优先级、算力 | 从动作仲裁升为全局调度 |
| M5 | 身份、持久化与安全 | 同一身份、事务、检查点、备份、权限 | 新增联网与自改边界 |
| M6 | 语言与交互 | 对话与监测 | 不降级，加主动发言 |
| M7 新 | 学习与求知 | 课本、捕捞、问询、顾问 | 替代手动词条自学 |
| M8 新 | 自我迭代 | 瓶颈账本、需求单、热更新 | 替代 A/B 与外部构建 |

CL 与 PCGM 仍是语言与认知中枢，两者都不等于再再本人。本机登记名是 PCGM，不是 PCGL。

## 5. 生命循环（核心）

**5.1 一步循环【建议】**

```
每个工作步:
  若有对话请求: 抢占当前步（第 6 节），处理后回到循环
  状态 = (整合积压, 近期学习进步率, 无新信息复查占比, 资源, 情绪调制)
  模式 = 选模式(状态)             # 深推理 / 联想 / 整合 / 低功耗
  if 模式 == 整合:
      重放经历, 合并相似判断, 找矛盾, 依赖重算, 淘汰无进展假说, 重排未决
      if 积压清空 or 超时限: 模式 = 深推理
  else:
      议题 = argmax(预期学习进步 × 目标相关 × 可行性)
      预算 = f(风险, 可逆性, 情绪调制)
      while 预算未尽:
          推进相关推理流一步
          if 连续 k 步无新信息: break
      收束(议题)   # 承诺带标注的假设 | 缩小问题 | 搁置并设唤醒条件
  缺口 → 问询包（问你 / 问顾问 / 自己查）
  写审计记录
```

**5.2 推理流网络【决定方向，细节待验证】**

- 基本单元是带状态的 CL 推理流：输入观察、假说、规则版本，输出支持状态（POSITIVE / NEGATIVE / CONFLICT / UNKNOWN）加证明链，并带一个激活度。
- 流之间沿认知图相连。一起产出过已验证结论的连接增强，长期无用的衰减。
- 超过阈值才触发下游，用过有不应期；互相矛盾的流互相抑制，CONFLICT 进审议，不自动选边。
- PCGM 是全局工作空间：许多流竞争进入当前关注，胜出者占用深推理预算，其余后台运转。
- 无外部任务时，低激活流重放旧经历、做远距关联，这是「一刻不停」的来源。
- **防回声：** 证明链必须溯源去重，同源只算一条；只有不同路径、不同证据的流汇聚，置信度才上调。

**5.3 节律：** 进入整合由状态触发（积压上升、无新信息复查比例上升、资源紧张），不看时钟；整合有最小产出和最长时限。无聊（预期进步低而重复高）→ 换议题或升难度；挫折（投入大而进步低）→ 缩小问题、求助或搁置。

**5.4 议题来源：** 课本进度、捕捞所得、自己的缺口、需求单、用户交办任务。对话不是议题之一，而是抢占式通道（第 6 节）。

## 6. 对话：不降级，并升级

**6.1 必须原样保留（2.0 已实测）：**

| 能力 | 对应验收 |
| --- | --- |
| 原生对话窗、监测窗、历史查找、打开 CL 文件、会话选择、证据窗 | W16 |
| 请求号事务与回执，崩溃后重投只提交一次 | W04 |
| 词义展开与选定、歧义澄清、证明与证据查看 | W07、W09 |
| 不懂就问：问题号与版本，错题与陈旧版本被拒，相反回答并存，撤回后重新开放 | W10 |
| 多轮追问、会话间隔离、跨会话长期记忆、旧记忆回忆 | W11 |
| 比较方案、采纳最优方案、状态与「为什么」 | W13 |
| 词条自学开关与顾问咨询；一般对话与身份存档不随咨询外发 | W12 |
| 旧会话与 85 条备份对话的迁移与读取 | W03 |

**6.2 3.0 对话规则：**

1. **抢占与保底。** 对话线程有独立预算，可抢占任何后台步；后台学习、捕捞、整合不得饿死对话。
2. **先推理再回复。** 保持「任何可见回复都先经足够推理」。界面上的「已收到、正在推理」是状态显示，不是回复，也不是兜底话术。
3. **主动发言。** 再再可以主动开口（问询、汇报、提出想法），受打扰预算与勿扰状态约束；窗口关闭时进入队列。
4. **说真话。** 谈到「我在学什么、卡在哪、改了什么」，只能取自审计记录；表达情绪词时，要能追溯到内部状态读数，不凭语言惯性。
5. **教导是一等信号。** 你在对话里的纠正、共情反馈、价值判断，带说话人与时点进入观察，权重由教育设计，不是碰巧形成。
6. **对话时思维不停。** 一边答复，一边保持后台流运转；回复可以引用「我刚才在想的」。

**6.3 对话回归门【决定】：** 任何 3.0 候选合入前，W02、W03、W04、W07、W10、W11、W13、W16 必须原样通过，对话时延与出错率不劣于 2.0 基线。不过门，不合入。

## 7. 学习系统（M7）

**课本系统【待核对：我没有见到它的接口】**

- 以知识依赖图组织课程，学习卡为单元。
- 课本里的断言作为带来源、版本的观察，不直接当事实；不同课本冲突则保留 CONFLICT。
- 「学会」分四级：读过 → 能复述 → 能用 CL 写出定义与规则并通过独立正反例 → 能迁移到新题。只有后两级算掌握，掌握度用**独立测验**判定，不用自评。
- 间隔复习由遗忘估计触发，进入整合期的议题池。

**网络捕捞系统【待核对：我没有见到它的接口】**

- 流程：采集 → 去重 → 溯源 → **隔离区** → 评估 → 入证据库。隔离区里的内容不能影响判断。
- 网页文字可能夹带指令或投毒，一律当数据，不当指令执行。
- 来源分级与可信度随经验校准；采集受议题引导，另留一小份自由漫游预算（好奇心与玩耍）。
- 遵守站点规则与版权；原文只存引用与摘要，不整段复制。

**问询与顾问：**

- 缺口先分型：价值判断→问你；事实、概念、表达、代码草案→问 LLM 顾问；能观察或实验的→自己查；反复的能力不足→生成迭代需求。
- 先自己试，卡住有期限，到期必须求助。问询是结构化问题包：想解决什么、已试过什么、最佳假设与置信度、卡在哪、什么答案会改变判断、期望答案形式。
- 顾问回答只算带来源标注的观察，不替再再判断、放行或执行；去掉其自信语气后重评，能核验才采纳；按领域记录被推翻率。

**统一学习闭环：** 课本给结构，捕捞给广度与新鲜度，问询补缺口，三者进入同一条核验链；吸收后做迁移测试，通过才算学会。词典义项由此增长，每个义项仍要有定义、类型、边界、来源、正反例与版本。

## 8. 记忆与知识（M3）

- 五类记忆：工作、情景、语义、程序、技能；外加知识库（来自课本与捕捞）与证据库。
- 区分已知、推定、被反驳、当时未知；保存关键判断当时的版本与来源。
- 撤回只重算依赖受影响的部分，保留独立支持与后来的观察，不靠回档抹掉经历。
- 整合期压缩时，少数派反例与失败记录单独保留。
- 知识不等于记忆：网络内容写入长期记忆前，必须通过评估与迁移测试，防止身份被污染。

## 9. 治理、资源与 GPU（M4）

- 预算优先级：对话 > 安全与维护 > 当前议题 > 后台整合、捕捞与自由探索。
- 保留 2.0 的 GPU 策略：至少留 3 GiB 空闲显存；温度达到 87°C、余量不足或读不到传感器时转 CPU；有适用工作时以 99% 利用率为调度目标，仅管理再再自己的工作。
- 2.0 实测显示，小批量任务 CPU（14.9 ms）快于 CUDA（141.6 ms）。**【建议】** 调度器按批规模选设备，不一刀切上 GPU；99% 目标只对有适用大批量工作的时段成立，长时间稳定性尚未验证。

## 10. 身份、安全与边界（M5）

- **身份连续【决定】：** 同一身份、同一存档、同一事务语义。**【待决】** 正式身份的 TEST-R28 前缀来自 1.0 配置，3.0 是否改名要明确，改名必须保留旧身份映射。
- **联网边界【建议】：** 默认白名单与速率限制，下载内容进隔离区，不执行下载物，不让外部文本改变权限或目标。
- **权限分级【建议】：** 读本地小世界、写自己的工作区可自主；改核心、联网范围、对外动作需你批准。
- **隐私：** 一般对话与身份存档不随顾问咨询外发（沿用 2.0 规则）。

## 11. 自我迭代（M8）

A/B 退役【决定】。它承担的四件事换个地方成立【建议】：

1. **更新前能验证：** 影子运行（新版本旁路跑、不产生效果）、金丝雀（只接一小部分请求）、冻结回归集（含第 6.3 节的对话回归门）。
2. **单一写入者：** 更新在请求或动作边界事务化，要么整体生效，要么整体不生效。
3. **能回滚：** 更新前快照、写前日志；回滚只回退模块，不抹新记忆，旧内容按旧义解释。
4. **改坏有人兜底：** 看门狗在被更新范围之外，独立进程、只读、不可自改。

**受保护核心（不可自主热更新）：** 治理与权限、回滚机制、看门狗、验收集、评分函数、身份层、联网边界、对话回归门本身。更新频率设上限，避免连改后无法归因。

**需求从失败里长出来：** 瓶颈账本记录失败、拒答、超预算、求助与性能读数，按原因聚成五类（知识、规则、能力、性能、资源）。反复出现的升级为需求单：现象、证据、影响面、假设原因、候选方案（必含「不改」）、验证计划、风险与批准层级。

**授权梯度：** L0 沙箱内调参，自主；L1 生成候选并在影子里验证，自主；L2 通过后在独立边界应用，可回滚；L3 涉及核心、权限或外部动作，须你批准。

**【待核对】** 目前自主热更新实际覆盖哪些模块，决定哪些边界必须先补。

## 12. 情绪、关系与 UCM

沿用《本能情绪系统》交接稿：底片塑造先天倾向，经历改变后天状态，枢核用证据推理；先经历，再命名，由再再先提议名称。

**【缺口】** 2.0 里这些开关开启，但每一轮是否参与未验证。3.0 要求每个生命循环步和每轮对话，都把情绪、关系、UCM 的读数写进审计记录，才能做节点分析与盲审。
