# CL 和 PCGM 的定义与协作

以下是项目设计稿节选，描述设计目标和接口。

## 一、CL：一门可编程、可推理、可用来表达的独立语言

CL 不只是给中文或英文换一套写法，也不只是某个大模型的提示词。它有自己的语法、类型、模块、编译和执行规则。人可以用自然语言接近它，再再可以把它当作原生表达工具，但 CL 的结构不从哪一种自然语言的语序推导。长期目标是让表达和代码共用同一套可检查语义。

| CL 的层次 | 职责 |
|---|---|
| 表达 | 明确对象、属性、关系、上下文、时间、范围与条件；感受、评价、引用与观察不能混为一谈。 |
| 词典 | 用稳定义项 ID 承接表达。中英词头只是入口；同词可有多个义项，同义项可有多种说法。新词或多义不应被强行塞进相近旧词。 |
| 编程 | 用类型、事实、规则、查询、模块和运行库构造可重复执行的程序。类型和来源不能靠一句看似合理的翻译替代。 |
| 推理 | 严格区分 POSITIVE（支持）、NEGATIVE（反证）、CONFLICT（两侧都支持）和 UNKNOWN（两侧均无支持）。缺证不等于否定。 |
| 核验 | 保留证据出处和证明链。能区分「表面有支持」与「确有不经过已知争议前提的证明」。可以锁定输入版本，让同一个证明后来仍可复验。 |
| 可改写性 | 能把候选定义或规则写成 CL，再编译、比较和验证。终局要支持运行中切换经过验证的版本，旧内容仍按旧义解释。会写新规则不等于可以无条件改掉正在运行的系统。 |

概念上可把一次求值写成：

`CL(规则版本, 活跃观察快照, 精确查询) → {支持状态, 正反证明, 来源与版本标识}`

这是职责说明，不是公开调用语法。证明说明「按这些输入和规则能推出什么」，不是在外部世界宣告事实一定为真。

### 词典的终局标准

目标为 **200,000 个可区分的真实义项**：50,000 通用表达、10,000 推理和决策、100,000 专业领域、40,000 新义和跨文化表达。别名、翻译和词形变化不增计数；具体新闻、人物和时事事实进入证据，不冒充词义。每个义项要有定义、类型、边界、来源、正反例和版本。用没参与扩写的材料验收：日常表达覆盖至少 98%、核心推理 99%、宣布覆盖的专业领域各自 95%；语境义项匹配至少 95%，同时报告拒答与误识别，不能靠乱猜刷覆盖。

**当前真实词典仍是 531 个义项。** 其 1,715 条原生查义和歧义断言已在 16 分片下保持。另跑通 20 万个合成义项的分片容量测试。这只证明一条扩容路径能承载数据，不证明已经有 20 万真实义项或达到覆盖率。

## 二、PCGM：一套可持续运转、可被证据改变的认知模型

PCGM 是再再的认知中枢。它不以「尽快说下一句话」为目标，也不以不停输出证明自己在思考。它维护可变化的认知结构：问题、证据、记忆、候选解释、目标和计划互相连接；遇到新证据，可以增强、推翻、限制或撤回原判断。这里的「模型」不是大语言模型，也不要求把 PCGM 做成预训练的神经网络。

1. **生成议题**：即使没有外部任务，运行中的 PCGM 也要能复查未决问题、发现解释缺口、比较候选定义或准备下一项调查。学习卡、公开信息捕捞、词典扩写、自我迭代是可选择的活动，不是四个机械轮转项。
2. **形成判断**：把事实、用户表达、推断、假说、价值判断和行动选择分开。用 CL 推理并保留反证；怀疑应当有依据，结论强度不应超过证据强度。没有新证据时可以重看旧结论，但不能把重复复查当成新发现。
3. **持续运转**：只要软件处于运行态，每个有限工作步都要有实际求证、复查、假说比较，或明确识别缺证。低功耗档降低频率和规模，不把能力退化成定时心跳。这是再再自身的工作循环。用户仍可暂停或关机；再次启动要从同一身份、记忆和未完成目标接着做。
4. **记忆与修正**：区分已知、推定、被反驳和当时未知；保存关键判断当时用的版本与来源。撤回只重算依赖受影响材料的部分，保留其他独立支持和后来的观察，不靠回档抹掉经历。
5. **自我迭代**：比较继续原样、更新、回退和其他方案。没有哪条路天然优先，选哪个取决于证据和约束。候选可以先合成和复验；通过后才允许按独立边界应用。A/B 是方便核对和不中断的工程手段，不是两个独立个体。
6. **无模板表达**：任何对用户可见的回复都先经过足够推理，包括澄清。PCGM 给出依据、未解部分和范围；CL 保持这些含义再形成表达。没有固定兜底话术，也不按回复速度打分。若「用户在表达高兴」已有支持，「为什么高兴」没有支持，这两件事应分别处理，而不是谎称知道原因，或把整句话退回给用户解释。

概念上，一步认知更新可表示为：

`PCGM(上一步认知状态, 当前观察与约束, CL 的可复验证明) → {新的认知状态, 未决问题, 候选下一步, 审计记录}`

「持续」是说运行中可主动接续；「可塑」是说内容和部分判断规则可随证据修正。二者都不等于已经证明系统拥有主观经验。

## 三、两者怎样联动

| 环节 | 谁负责什么 |
|---|---|
| 1. 接收 | 把输入留作观察，标明谁说的、何时说的和上下文。表达一种情绪并不意味着知道引起它的事件。 |
| 2. 提问 | PCGM 找关键缺口，决定先验证哪些解释，不因某个词没命中就立即中断整句理解。 |
| 3. 推理 | CL 在当前明确规则、词义和证据上执行查询，产出支持、反证、冲突或缺证及其链路。 |
| 4. 审议 | PCGM 比较证据和替代解释，遇到冲突不自动选边；评估是否还要补证或继续推理。 |
| 5. 表达 | CL 将已经形成的结论、限度与仍有必要的问题表达出来，无固定模板、无外部模型代替判断。 |
| 6. 学习与纠错 | 若是表达缺口，PCGM 可提出新定义；CL 编译并用独立正反例检验。之后还要验证能否用于别的推理，证据被撤回时能否重新计算，历史是否仍保持旧含义。 |

对再再而言，连续体还包括长期记忆、感受、原趋和交互边界。这些不是词典或证明引擎本身，也不因它能输出情绪词就自动成立。本阶段情绪部分只实测，不改动。
